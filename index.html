CSE 427 · Wireless Sensor Networks · Week 6 assignment

Follow one reading through the stack

You will build a small multi-hop CoAP network in Cooja, capture what goes over the air, and use your own packets to explain names, addresses, routes, 6LoWPAN compression, fragmentation and CoAP. Then you prove it in a video of at most 10 minutes.

PlatformInstant Contiki 3.0 · Cooja · Wireshark
Hands-on timeAbout 3 hours
Video10:00 maximum, your voice, your screen
You submitVideo · .pcap capture · worksheet

What the assignment covers

Week 6 tells one story: what the application wants (a name), where it lives (an address), how to reach it (a route), and how to fit IPv6 into a 127-byte radio frame (6LoWPAN). Every experiment below checks one part of that story against real frames from your own simulation.

?FAQ: Instant Contiki & Cooja

Read this once before you start. Most problems in this assignment come from the VM, from Cooja, or from the Sky mote's small memory, not from your code. Find your error message below.

The virtual machine
Which VM, and which login?

Instant Contiki 3.0. Log in as user with password user; sudo asks for the same password. It ships as a VMware image and runs in the free VMware Workstation Player.

Can I use VirtualBox instead of VMware?

Yes. Create a new VM of type Linux / Ubuntu (32-bit), choose Use an existing virtual hard disk, and select the .vmdk file from the download that has no -s00… suffix. Give the VM at least 2 GB of RAM and 2 CPUs; Cooja is slow with the default 512 MB.

I have an Apple Silicon Mac (M1, M2, M3, M4)

Instant Contiki is a 32-bit x86 VM. VirtualBox and VMware on Apple Silicon run ARM guests only, so the VM will not boot there. UTM can emulate x86, but Cooja becomes very slow. Use a lab PC or any Windows/Linux laptop with an Intel or AMD CPU, and tell your instructor early if you have no access to one.

My keyboard types the wrong characters (| # < > [ ])

The VM defaults to a US keyboard layout. Add your layout (for example Turkish Q) in the VM's keyboard / text entry settings and select it from the top bar, or learn where the US keys are. Check this before you type C code.

Where is Contiki? My path is not ~/contiki

Run ls ~. Most copies of Instant Contiki 3.0 use ~/contiki; some downloads unpack to ~/contiki-3.0. If yours differs, replace ~/contiki in every command on this page.

How do I get my .pcap and video files out of the VM?

Use a shared folder (VMware: VM → Settings → Options → Shared Folders; VirtualBox: Devices → Shared Folders), drag-and-drop if guest tools are installed, or a USB stick passed through to the VM. You need the .pcap files for your submission, so test this early.

Cooja
ant run fails: "Could not find the MSPSim build file"
BUILD FAILED .../tools/cooja/build.xml: ... Could not find the MSPSim build file. Did you run "git submodule update --init"?

The MSPSim simulator (needed for Sky motes) is a git submodule that is missing in some downloads. With internet access in the VM, run:

cd ~/contiki git submodule update --init cd tools/cooja ant run

Do not use sudo for ant run.

I ran something with sudo and now I get "Permission denied"

Files created with sudo belong to root. Give them back to your user: sudo chown -R user:user ~/contiki. Only make connect-router-cooja needs sudo, and it asks for it by itself.

Cooja is very slow or freezes

Give the VM more RAM and CPUs. Start Cooja with ant run_bigmem for more Java memory. Close plugins you are not using. Keep the Radio messages window closed until you need a capture: logging every frame costs time.

Where is the button? Where is "Change transmission ranges"?

Both are context menus. Right-click a mote in the Network window for Click button on Sky n and Mote tools for Sky n. Right-click an empty area of the Network window for Change transmission ranges (only with the UDGM radio medium).

I changed my code, but the motes still run the old firmware

Run make TARGET=sky clean in ~/contiki/examples/cse427-w6, then File → Reload simulation. Both boot messages (W6 server, REST_MAX_CHUNK_SIZE=… and W6 client up) tell you which build is running.

Mote type compilation fails with "No rule to make target" or "cannot run program make"

The source file is in the wrong folder, or the path contains spaces. Keep every file directly in ~/contiki/examples/cse427-w6/, next to the Makefile, and browse to that folder in the Create mote type dialog.

Building for Sky motes
Why not just use the stock er-example-server?

A Sky mote has 48 KB of flash and 10 KB of RAM. The stock Erbium server compiles all of its example resources, and with Instant Contiki's msp430-gcc it is known to overflow the Sky's flash. That is why Step 2 builds a separate project with only the two resources you need.

"section .text will not fit in region rom"

Flash is full. Check that the Makefile lists only res-student.c res-separate.c, that SMALL = 1 is set, and that project-conf.h uses nullrdc_driver and nullmac_driver. Measure with msp430-size (Step 4b).

"region .bss overflowed", "UIP_CONF_BUFFER_SIZE too small", or a mote reboots during the big response

RAM is full or the stack is overwriting data. In project-conf.h, lower COAP_MAX_OPEN_TRANSACTIONS to 1 and NBR_TABLE_CONF_MAX_NEIGHBORS / UIP_CONF_MAX_ROUTES to 4, then rebuild. If it still fails, tell your instructor your L; it may need a lower cap.

"undefined reference to res_student" (or res_separate)

The resource file is not being compiled. Check that res-student.c and res-separate.c are in the project folder and listed on the PROJECT_SOURCEFILES line of the Makefile.

Border router and RPL
tunslip6: "can't connect to 127.0.0.1:60001: Connection refused"

Cooja is not listening yet. Start Serial Socket (SERVER) on node 1, click Start in it, start the simulation, and only then run make connect-router-cooja.

tunslip6 fails because tun0 is busy, or a second copy is running

An old tunslip6 from a previous run still holds the tunnel. Stop it with sudo killall tunslip6, then run make connect-router-cooja again. Do this every time you reload the simulation.

The client prints "No global address yet" forever

The border router never received its prefix, or the motes cannot hear each other. Check that tunslip6 printed Server IPv6 addresses, and that every mote's green range circle reaches its neighbours. RPL needs up to a minute of simulated time to form; wait before you worry.

The client prints "--Done: 0 bytes--" for every request

SERVER_NODE does not match node 2's address (read it from node 2's output), or RESOURCE_PATH in the client differs from the path in rest_activate_resource in the server. Both paths must be identical, with no leading slash.

My border router prints aaaa:: addresses, not fd00::

Use your border router's prefix everywhere: in SERVER_NODE, in ping6, and in Wireshark's 6LoWPAN context 0.

Capture and Wireshark
Where is the .pcap file?

Cooja writes it as radiolog-<number>.pcap in the folder where Cooja is running, usually under ~/contiki/tools/cooja. The find command in Step 7 locates it. Every new capture creates a new file.

The .pcap file is empty or ends early

Cooja may still hold data in memory. Pause the simulation and close the Radio messages window (or quit Cooja) before you copy the file.

Wireshark shows "Bad FCS" or does not decode 6LoWPAN

Cooja's pcap uses the 802.15.4 link type that expects a 2-byte checksum (FCS) at the end of each frame, and simulated frames may not carry a valid one. In Preferences → Protocols → IEEE 802.15.4, turn off the option that dissects only frames with a good FCS, or change the FCS format. The option names differ between Wireshark versions.

Addresses in Wireshark look wrong or shortened

Set Preferences → Protocols → 6LoWPAN → Context 0 to fd00::/64. IPHC removed the prefix from the frames, and Wireshark needs the context to restore it.

Every frame appears many times

ContikiMAC is running on at least one mote type: it repeats each frame until the receiver wakes up. Check the NETSTACK_CONF_RDC lines in both project-conf.h files, run make TARGET=sky clean in both folders, and reload.

I see no link-layer retransmissions at all

Expected: nullmac_driver has no retry logic, which saves flash. Only CoAP retransmits in this setup. This matters for the bonus question.

The assignment
Can I use Z1 motes, Contiki-NG, or my own laptop's Contiki install?

No. Use Instant Contiki 3.0 with Sky motes, so that every capture follows the same frame formats and the rubric is fair.

My predicted fragment count is off by one

Check two things: 8-byte alignment of fragment payloads, and whether you used the compressed or uncompressed datagram size. That difference is exactly what E3 wants you to explain, so keep the wrong prediction on your worksheet and explain it.

Can my video be shorter than 10 minutes?

Yes, if it covers every part of the rubric. Anything after 10:00 is not graded.

#ifndef PROJECT_CONF_H_
#define PROJECT_CONF_H_

#undef  NETSTACK_CONF_RDC

#undef  NETSTACK_CONF_MAC

/* 6LoWPAN fragmentation on */
#undef  SICSLOWPAN_CONF_FRAG
#define SICSLOWPAN_CONF_FRAG        1

/* IP buffer: must hold COAP_MAX_HEADER_SIZE + REST_MAX_CHUNK_SIZE + 48 */
#undef  UIP_CONF_BUFFER_SIZE
#define UIP_CONF_BUFFER_SIZE        300

/* THE KNOB. Config B (E1 to E4): 200. Config A (E5): your block size B. */
#undef  REST_MAX_CHUNK_SIZE
#define REST_MAX_CHUNK_SIZE         200

/* Save RAM: Sky motes have 10 KB */
#undef  COAP_MAX_HEADER_SIZE
#define COAP_MAX_HEADER_SIZE        40
#undef  COAP_MAX_OPEN_TRANSACTIONS
#define COAP_MAX_OPEN_TRANSACTIONS  2
#undef  COAP_LINK_FORMAT_FILTERING
#define COAP_LINK_FORMAT_FILTERING  0
#undef  COAP_PROXY_OPTION_PROCESSING
#define COAP_PROXY_OPTION_PROCESSING 0

#undef  UIP_CONF_MAX_ROUTES

The border router must use the same radio duty cycling, or it cannot talk to your motes. Open examples/ipv6/rpl-border-router/project-conf.h and add these lines just above its final #endif (skip this if they are already there):

rpl-border-router/project-conf.h · add at the bottom
#undef  NETSTACK_CONF_RDC
#define NETSTACK_CONF_RDC  nullrdc_driver
Why these settingsREST_MAX_CHUNK_SIZE is the largest CoAP payload one message may carry. At 200, your whole 157-byte payload goes in one CoAP response that is too big for one radio frame, so 6LoWPAN must fragment it (Config B). In E5 you lower it to 64, and CoAP splits the payload into blocks itself (Config A).

3Your resource and the server

Create res-student.c in the project folder. The payload is predictable (byte k is the letter 'A' + k mod 26), so you can check block numbers and fragment offsets by eye in Wireshark.

cse427-w6/res-student.c · new file
/* CSE 427 Week 6: a resource whose size you control */
#include <string.h>
#include "rest-engine.h"

#define PAYLOAD_LEN  157   /* L from Step 0 */

static void res_get_handler(void *request, void *response, uint8_t *buffer,
                            uint16_t preferred_size, int32_t *offset);

RESOURCE(res_student,
         "title=\"Week 6 sensor\";rt=\"Text\"",
         res_get_handler, NULL, NULL, NULL);

/* Byte k of the representation is 'A' + (k % 26). */
static void
fill(uint8_t *buffer, int32_t start, int32_t n)
{
  int32_t i;
  for(i = 0; i < n; i++) {
    buffer[i] = 'A' + ((start + i) % 26);
  }
}

static void
res_get_handler(void *request, void *response, uint8_t *buffer,
                uint16_t preferred_size, int32_t *offset)
{
  int32_t n;

  REST.set_header_content_type(response, REST.type.TEXT_PLAIN);

  /* Config B: the whole representation fits in one CoAP message. */
  if(*offset == 0 && preferred_size >= PAYLOAD_LEN) {
    fill(buffer, 0, PAYLOAD_LEN);
    REST.set_response_payload(response, buffer, PAYLOAD_LEN);
    return;                /* offset untouched, so no Block2 option */
  }

  /* Config A: serve one block that starts at *offset. */
  if(*offset >= PAYLOAD_LEN) {
    const char *msg = "BlockOutOfScope";
    REST.set_response_status(response, REST.status.BAD_OPTION);
    REST.set_response_payload(response, msg, strlen(msg));
    return;
  }
  n = PAYLOAD_LEN - *offset;
  if(n > preferred_size) {
    n = preferred_size;
  }
  fill(buffer, *offset, n);
  REST.set_response_payload(response, buffer, n);

  *offset += n;            /* tells Erbium this resource is block-aware */
  if(*offset >= PAYLOAD_LEN) {
    *offset = -1;          /* -1 marks the last block */
  }
}

Now create the server. It serves only your resource and the separate-response demo you copied in Step 2. Pressing the server's button releases a waiting separate response (you need this in E4).

cse427-w6/wsn-server.c · new file
/* CSE 427 Week 6 server */
#include <stdio.h>
#include "contiki.h"
#include "contiki-net.h"
#include "rest-engine.h"
#include "er-coap-engine.h"
#include "dev/button-sensor.h"

extern resource_t res_student, res_separate;

PROCESS(wsn_server, "CSE427 W6 server");
AUTOSTART_PROCESSES(&wsn_server);

PROCESS_THREAD(wsn_server, ev, data)
{
  PROCESS_BEGIN();
  PROCESS_PAUSE();

  printf("W6 server, REST_MAX_CHUNK_SIZE=%u\n", REST_MAX_CHUNK_SIZE);

  rest_init_engine();
  rest_activate_resource(&res_student, "sensors/yilmaz");
  rest_activate_resource(&res_separate, "test/separate");

  SENSORS_ACTIVATE(button_sensor);

  while(1) {
    PROCESS_WAIT_EVENT();
    if(ev == sensors_event && data == &button_sensor) {
      printf("Button: sending the separate response\n");
      res_separate.resume();
    }
  }

  PROCESS_END();
}

4Write the client

Create wsn-client.c in the project folder. It waits until RPL gives it a global address, then sends a confirmable GET to your resource every 20 seconds. Pressing its button sends one GET /test/separate. Every request carries a 2-byte Token 06 nn, where nn counts requests, so you can match requests to responses.

cse427-w6/wsn-client.c · new file
/* CSE 427 Week 6 client */
#include <stdio.h>
#include <string.h>
#include "contiki.h"
#include "contiki-net.h"
#include "net/ipv6/uip-ds6.h"
#include "er-coap-engine.h"
#include "dev/button-sensor.h"

/* Global address of node 2, your target server. Confirm it in node 2's output. */
#define SERVER_NODE(ipaddr) \
  uip_ip6addr(ipaddr, 0xfd00, 0, 0, 0, 0x0212, 0x7402, 0x0002, 0x0202)

#define RESOURCE_PATH     "sensors/yilmaz"
#define REQUEST_INTERVAL  20      /* seconds between requests */
#define REMOTE_PORT       UIP_HTONS(COAP_DEFAULT_PORT)

PROCESS(wsn_client, "CSE427 W6 client");
AUTOSTART_PROCESSES(&wsn_client);

static uip_ipaddr_t server_ipaddr;
static struct etimer et;
static uint16_t received;
static uint8_t req_no;
static uint8_t token[2];

static void
on_response(void *response)
{
  const uint8_t *chunk;
  int len = coap_get_payload(response, &chunk);
  received += len;
  printf("  got %d bytes (total %u)\n", len, received);
}

static void
prepare(coap_packet_t *request, const char *path)
{
  coap_init_message(request, COAP_TYPE_CON, COAP_GET, 0);
  coap_set_header_uri_path(request, path);
  token[0] = 0x06;          /* week 6 */
  token[1] = ++req_no;      /* a new Token for every request */
  coap_set_token(request, token, 2);
  received = 0;
}

PROCESS_THREAD(wsn_client, ev, data)
{
  static coap_packet_t request[1];

  PROCESS_BEGIN();

  SERVER_NODE(&server_ipaddr);
  coap_init_engine();
  SENSORS_ACTIVATE(button_sensor);
  etimer_set(&et, REQUEST_INTERVAL * CLOCK_SECOND);
  printf("W6 client up. Button = GET /test/separate\n");

  while(1) {
    PROCESS_YIELD();

    if(etimer_expired(&et)) {
      if(uip_ds6_get_global(ADDR_PREFERRED) == NULL) {
        printf("No global address yet (RPL not joined)\n");
      } else {
        prepare(request, RESOURCE_PATH);
        printf("--GET /%s token 06%02x--\n", RESOURCE_PATH, req_no);
        COAP_BLOCKING_REQUEST(&server_ipaddr, REMOTE_PORT, request, on_response);
        printf("--Done: %u bytes--\n", received);
      }
      etimer_reset(&et);

    } else if(ev == sensors_event && data == &button_sensor) {
      prepare(request, "test/separate");
      printf("--GET /test/separate token 06%02x--\n", req_no);
      COAP_BLOCKING_REQUEST(&server_ipaddr, REMOTE_PORT, request, on_response);
      printf("--Done: %u bytes--\n", received);
      if(etimer_expired(&et)) {
        etimer_restart(&et);
      }
    }
  }

  PROCESS_END();
}

Write down nowThe interface identifier is the radio address with one bit flipped (00:12… becomes 02:12…). Which bit is it, and why does that matter for compression in E2? You will need this in the video.

5Build the topology in Cooja

  1. File → New simulation. Keep the radio medium as Unit Disk Graph Medium (UDGM): Distance Loss. Click Create.
  2. Motes → Add motes → Create new mote type → Sky mote. Browse to examples/ipv6/rpl-border-router/border-router.c, click Compile, then Create, and add 1 mote. It becomes node 1.
  3. Create a second Sky mote type from cse427-w6/wsn-server.c and add 3 motes. These become nodes 2 to 4. Node 2 is your target. The others only forward packets.
  4. Create a third Sky mote type from cse427-w6/wsn-client.c and add 1 mote. It becomes node 5.
  5. Right-click in the Network window, choose Change transmission ranges, and set TX range 50 m and interference range 100 m.
  6. Drag the motes into one line, 40 m apart, in node-ID order. Turn on View → Radio environment (UDGM) and click each mote: its green circle must contain only its direct neighbours. This forces every packet to cross 3 hops.
  7. Open Tools → Mote output, then File → Save simulation as w6-yilmaz.csc.

6Connect the border router

In Contiki 3.0, the border router waits for its IPv6 prefix from the host over SLIP. Until it receives one, there is no RPL network and no node gets a global address.

  1. Right-click node 1 and choose Mote tools for Sky 1 → Serial Socket (SERVER). Keep port 60001 and click Start.
  2. Click Start in the Simulation control window.
  3. In a second terminal, run the command below (password user):
terminal 2
$ cd ~/contiki/examples/ipv6/rpl-border-router
$ make connect-router-cooja
# wait for: Server IPv6 addresses: fd00::212:7401:1:101 ...

# terminal 3: check that node 2 is reachable through the RPL network
$ ping6 -c 3 fd00::212:7402:2:202

Within about a minute, the client's output should change from No global address yet to --GET /sensors/yilmaz… followed by --Done: 157 bytes--. You can also open http://[fd00::212:7401:1:101]/ in the VM's Firefox to see the border router's neighbour and route tables.

7Start the capture

  1. Open Tools → Radio messages. In that window's menu, choose Analyzer → 6LoWPAN Analyzer with PCAP. From now on, every frame is also written to a .pcap file.
  2. Let at least 3 requests complete, then pause the simulation. Find the file:
terminal 3
$ find ~/contiki/tools/cooja -name "radiolog-*.pcap" -newer ~/contiki/examples/cse427-w6/wsn-client.c
$ wireshark &

A recent Wireshark on your own laptop decodes 6LoWPAN better than the VM's older version, so you may copy the .pcap out of the VM and analyse it there. Set up Wireshark once:

  • Preferences → Protocols → 6LoWPAN → Context 0: fd00::/64. Without it, Wireshark cannot rebuild the global addresses that IPHC compressed away.
  • If frames show "Bad FCS" or "Malformed", change the FCS setting under Protocols → IEEE 802.15.4. Cooja's pcap may not carry the 2-byte checksum.
  • Add columns for these fields (right-click a field → Apply as Column): wpan.seq_no, wpan.src64, wpan.dst64, ipv6.hlim, coap.mid, coap.token.

UDP NHC rule (first byte 11110CPP): a port is sent in 4 bits only if it is in 0xF0B0–0xF0BF, and in 8 bits if it starts with 0xF0. Otherwise it is sent in full (16 bits). Read your two ports from the capture and work out:
